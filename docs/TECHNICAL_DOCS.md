# Техническая документация по эксплуатации

## 1. Назначение

Информационная система автоматизирует работу сервисного центра компьютерной компании: учет клиентов и техники, ведение заявок на ремонт по статусам, списание запчастей со склада, разграничение прав доступа сотрудников.

## 2. Требования к окружению

Для запуска готового exe: Windows 10/11 x64, установка .NET не требуется (self-contained сборка).
Для сборки из исходников: Windows x64, .NET SDK 8.0 или новее, Visual Studio 2022/2026 с рабочей нагрузкой «Разработка классических приложений .NET».

## 3. Установка и запуск

Вариант 1. Распаковать архив из Releases и запустить ComputerServicePM05.exe.
Вариант 2. Собрать из исходников: dotnet run в каталоге проекта.
Вариант 3. Опубликовать exe: команда publish приведена в README.md.

При первом запуске рядом с исполняемым файлом автоматически создается база данных Computer_service.db со схемой и начальными данными (роли, статусы, категории, учетные записи admin и user).

## 4. Структура приложения

- Program.cs — точка входа, инициализация базы данных
- DatabaseManager.cs — строка подключения и скрипт инициализации схемы
- Models/UserSession.cs — модель сеанса пользователя
- UiKit.cs — единый стиль компонентов, таблиц и сообщений
- EntityListForm.cs — базовая форма списка с поиском, таблицей и панелью действий
- LoginForm.cs — авторизация
- MainForm.cs — главное окно, меню, сводка
- ClientsForm / ClientCardForm — клиенты
- DevicesForm / DeviceCardForm — устройства
- RepairOrdersForm / RepairOrderCardForm — заявки на ремонт
- PartsPickForm — списание запчасти со склада
- PartsForm / PartCardForm — склад запчастей
- UsersForm / UserCardForm — учетные записи

## 5. База данных и резервное копирование

СУБД SQLite, файл Computer_service.db в каталоге исполняемого файла. Резервное копирование выполняется копированием файла при закрытом приложении. Восстановление — заменой файла. Схема и начальные данные: docs/database.sql.

Целостность обеспечивается внешними ключами (PRAGMA foreign_keys = ON) и транзакциями в операциях списания, возврата и удаления заявок.

## 6. Разграничение доступа

Роль «Администратор»: полный доступ, включая удаления и управление учетными записями.
Роль «Пользователь»: создание и изменение рабочих данных, без удалений, без управления складом и учетными записями.
Пароли хранятся в таблице users; отключенная учетная запись (is_active = 0) не проходит авторизацию.

## 7. Поиск и устранение неисправностей

- Ошибка базы данных при старте: файл базы удален или занят. Удалите поврежденный файл, база будет создана заново, либо восстановите копию.
- Невозможно удалить запись: запись связана с заявками; сначала закройте или удалите связанные заявки.
- Пользователь не может войти: учетная запись отключена администратором или введен неверный пароль.

## 8. Направления модернизации

Хеширование паролей, модуль продажи техники, печатные формы актов и квитанций, централизованная база данных для нескольких рабочих мест, журнал аудита действий пользователей.
